# Sprint 1 测试用例

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 新环境启动 | 安装 Node 24 LTS 和 pnpm，运行对应平台安装、启动脚本 | 打开本机 Dashboard，健康接口返回正常 |
| 任务表单 | 新建包含中文的任务并选择目标平台 | 回到任务列表，显示任务和已创建状态，可展开说明 |
| 校验 | 输入纯空白标题，或通过 API 提交无效平台及额外字段 | 保留表单内容并显示错误，列表没有无效记录 |
| 持久化 | 新建任务后正常退出 Hub，再次启动 | 任务 ID、目标平台、说明、状态和时间保持一致 |
| 系统设置 | 检测本机环境，运行 `pnpm exec devhub doctor --json` | 两端显示相同类型的检测项。终端 JSON 可解析，缺少基础工具时返回非零 |
| 本机访问控制 | 使用外部 Host 或外站 Origin 发起请求 | Hub 返回 403，任务数据未写入 |
| 目录兼容 | 在带空格与中文的路径启动，用自定义 Unity 安装位置运行 doctor | 正常启动，识别目标版本，Unity Editor 不启动 |
| 日志 | 写入含敏感字段的结构化日志 | 授权头、Cookie、令牌与密码字段被遮盖 |

自动化入口为 `pnpm test`。真实 Windows 安装、脚本和浏览器操作需要在 Windows 11 上实测。

## 2026-11-19 实测

- macOS 14.5 arm64，Node.js 24.22.3 LTS，pnpm 11.25.0。严格类型检查、Vitest 15 项和 Vite 生产构建通过。macOS 安装脚本使用锁文件完成安装和构建，启动脚本可从其他工作目录调用。
- Chrome 验证了空白标题校验、中文任务录入、平台选择、任务详情和环境刷新。390 px 宽度下没有横向溢出。
- 进程只监听 IPv4 回环地址。在带中文和空格的临时路径使用 SQLite，经停止并重新启动 Hub 后读回同一条任务，各字段一致。
- `devhub doctor` 通过基础检查，识别到 Unity 6000.3.28f1。传入工程路径时只读核对到相同版本。Codex CLI 检测覆盖 PATH 中的启动文件。
- Windows 模拟覆盖 `PATHEXT`、带空格和中文的路径、自定义 Unity Hub 根目录及 CRLF 工程版本文件。Windows 11 的 PowerShell 执行策略、pnpm 启动器、Vite 原生组件和本地 SQLite 文件权限仍待实机验收。
- 本机默认 Node 为 16，验证时通过当前会话的 PATH 选用 Node 24。macOS Intel 环境待实机验收。
