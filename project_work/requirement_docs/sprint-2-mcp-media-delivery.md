# Sprint 2.9 · MCP 媒体交付与 Unity 视频审查

## 范围

沿用 Hub 和 MCP Bridge 的配对、项目与 Run 归属验证、Artifact ID、审计和只读工具。截图返回 PNG 或 JPEG 的标准 ImageContent。录屏提供同一 Artifact 的标准 Resource Blob，视觉审查通过带时标的独立图像完成。Dashboard 沿用现有源文件和 Range 路由。

## 读取与预算

按已登记的 Project、Run、Artifact ID 定位源文件。使用 Artifact 存储的路径、文件标识及平台权限检查。对大小、文件签名、SHA-256 逐项校验。原图和原始录屏的单次原始字节上限为 3 MiB。超过原片传输上限的录屏仍可在独立输入预算内抽帧。

FFprobe 读取长宽、时长和帧率。FFmpeg 仅读取经过验证的私有临时副本，使用固定 demuxer、协议及参数。默认在均分时段内取样 8 帧，最多 12 帧。显式时间点优先，标注请求及实际帧时间。默认采样尽量跳过黑帧及完全重复帧，替代尝试后仍保留必要帧并标注原因。

聚合结果分开传送视频帧与阶段截图，按照整体响应预算选择 JPEG 编码质量。原始截图保留原尺寸和原字节。临时视频副本在完成、错误或取消时清理。并发重任务采用 Hub 全局限流，单任务及每次外部进程均有截止时间。

## 验收

分别记录本机 SDK、真实 ChatGPT MCP 图像、原片资源读取和客户端播放能力。现有 Unity 录屏资源用于只读验收。CI 覆盖 macOS 与 Windows 的同一测试契约。
