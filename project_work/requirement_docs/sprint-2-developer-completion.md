# Sprint 2.3C Developer Environment Completion

基于 `main@7b407564`。保留现有授权、SDK、脱敏事件和 Worker 监督。

## 实施与验收

1. 工作树快照在审批和领取时拒绝发现的秘密。PROJECT_DEVELOPER 继续限制宿主读取，并增加工作树秘密路径的原生读取拒绝。允许无凭据模板和正常 Unity 资源。
2. 增加按 Turn 授权的 CONNECT 依赖模式。Shell 保持网络 OFF，固定的依赖客户端在独立 OS 沙箱内只可访问当前回环代理。代理与模型传输分开。
3. macOS 真机执行合成秘密读拒绝、直连拒绝、依赖命令与 Unity 临时项目导入、构建。Windows CI 和 Windows 11 x64 桌面证据分别记录。
4. 保持进程组监督和不确定中断的工作树锁。记录可选 VM Runner 的隔离与恢复协议。

## 安全边界

权限变动通过新摘要和新授权交付。认证目录、源代码、会话历史、模型传输与依赖客户端保持分离。对外网络只支持公开域名。网络判定以实际沙箱和回环代理日志证据为准。

## 秘密文件保护规范

- 审批和领取扫描覆盖正常源文件、未跟踪项及普通忽略项。路径命中会拒绝运行，不打开该秘密文件。扫描发现私钥头、私有 npm 认证或模板内非占位认证值时返回固定错误码，值与路径不进入审计事件。
- SDK 额外通过原生命名权限拒绝读取常见秘密路径，包括新出现的标准 .env 文件、.npmrc、SSH 目录和 PEM/KEY。Windows 原生 glob 是每进程启动时快照，须以真实桌面实测。运行时不得向活动工作树拷入真实秘密或修改 ACL。自定义命名、二进制容器和人工注入需要独立秘密存储。
- `.env.example`、`.env.sample`、`.env.template` 和 `.env.dist` 允许无凭据模板。认证字段只填空值、描述性占位符或 `${ENV_NAME}`。只含公开注册表配置的 `.npmrc` 不触发审批拒绝，命令内统一用无认证配置。源代码、Unity 场景、Prefab、Shader 和项目设置沿用工作区权限。

## CONNECT 架构

DevHub 先校验工作树和授权摘要。SDK Shell 和旧 OFF 模式继续关闭网络。批准 `DEVELOPER_CONNECT` 后，SDK 可以调用固定的依赖客户端。macOS Seatbelt 将客户端及后代的 TCP 出站限制在本次代理的 localhost 端口，同时约束文件读取和写入。环境使用新的临时 HOME 和缓存，不继承模型代理或工作站凭据。若原生约束不可用，入口失败关闭。Windows 本阶段不开放 CONNECT。

代理绑定 IPv4 回环临时端口，并占用同端口的 IPv6 回环地址以拒绝连接。验证每次 CONNECT 的域名和 443，重新解析 IPv4，拒绝混有非公网地址的解析，然后固定连接实际地址。只转发目标匹配的 TLS ClientHello。拒绝 ECH。允许跨域重定向的客户端只使用 HTTP/1，Git 在禁止重定向的单域名隧道可使用 HTTP/2。TLS 保持端到端，HTTPS 响应原文和同源重定向在客户端解密，换域时由新的 CONNECT 重新授权。该层以 TCP 目标和 TLS SNI 为边界，不能从加密流中识别应用层域名前置。仅允许运行预定义的公共依赖客户端。

每个依赖命令新建代理。每个 Turn 最多四次依赖命令。每个代理上限为并发 6、80 次尝试、8 MiB 上行、128 MiB 下行、7 秒握手、20 秒空闲及 90 秒隧道。批准绑定实现版本、域名、模式和预算，临时端口在批准后分配。npm 与 pnpm 禁用生命周期脚本。Git 在临时 bare 仓库抓取公共远端并校验 FETCH_HEAD，原项目 `.git` 元数据仍归 Git Adapter。

代理启动后生成独立的 256-bit 随机秘密。每次 CONNECT 都要用 Basic `Proxy-Authorization` 认证，比较使用固定长度和常量时间函数。缺失、错误或重复认证头返回 407，并在域名查询和上游连接之前终止。普通 HTTP 请求返回 405。未经认证的请求不消耗有效凭据的连接尝试预算。关闭会停止监听、断开连接并清理服务端凭据缓冲区。

仅需要联网的受控客户端及其必要子进程接收代理凭据。Git 初始化和 FETCH_HEAD 校验使用无代理凭据的环境。版本和认证策略纳入授权摘要，实际凭据仅留在运行时。诊断只留计数，执行结果保留退出码，客户端输出丢弃，Seatbelt 禁止 npm 和 pnpm 的常见调试日志写入。凭据不进参数、Codex 环境、数据库或审计事件。具备读取同 UID 进程环境权限的主机进程仍可看到运行中的客户端环境，该威胁需要独立 OS 用户或 VM 隔离。

Unity 公共归档由受控客户端通过 CONNECT 下载，Unity Package Manager 使用 `file:` 引用从本地归档恢复。Editor 自身在同一代理沙箱内直连注册表的方案仍需完成原生进程启动和 IPC 验收。见 [Unity 本地归档依赖](https://docs.unity3d.com/6000.3/Documentation/Manual/upm-localpath.html)。

## 可选 macOS VM Runner

- 宿主继续持有 DevHub DB、审批与锁。为每次授予创建独立 VM 标识、generation 和一次性挑战。宿主校验虚拟化后端的进程身份与磁盘 attachment，Guest 通过隔离控制通道回报身份和心跳。
- Guest 只获得该工作树快照、只读基础镜像和独立临时写入盘。宿主凭据目录和 Git 元数据不挂载。模型登录需在 Guest 独立配置。网络使用 Guest 默认拒绝加宿主批准的代理出口。结果只由宿主校验后导入原工作树。
- 取消时先请求 Guest 正常退出，再由宿主管理 API 停止 VM。宿主只在同一 generation 的实例确认停止、写入盘确认卸载且工作树无其他租约时解锁。Guest 断联、管理 API 异常或盘状态未知时继续锁定。VM 停止时一并终止跨 Session 进程。
- 重启恢复需对照持久化的 VM ID、generation 和挂载身份，拒绝用同名 VM、PID 或超时推断退出。把异常锁恢复和产物导入做成独立审计动作。本阶段保留现有 macOS 进程组实现，VM 后端为技术方案。
