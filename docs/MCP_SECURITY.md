# DevHub MCP 安全边界

## 配对与共享范围

操作员在本机 Dashboard 选定项目和工具权限组并创建连接，管理请求使用已有 Cookie、精确 Origin 和 CSRF。每份配对使用 256 位随机凭据，SQLite 仅保存 SHA-256 摘要。轮换立即淘汰旧摘要，撤销或到期立即拒绝新调用。Hub 在返回异步结果之前再次校验原凭据。

只授予确认可以发送给 ChatGPT 的项目和权限组。MCP 配对是权限载体，拥有同一份本机凭据的程序共享授权范围。建议每个 Tunnel 使用独立配对。OpenAI 的连接认证及工作区共享规则由平台管理。DevHub 不将 Tunnel ID 视为用户身份。

操作员可在页面查看最近使用、传输、协议、权限和最近调用。审计只存连接 ID、允许范围内的项目 ID、工具名、时间和安全结果码。限流以连接为单位；无效的未认证请求没有对应连接记录。

## 本机传输

- Hub 和 MCP HTTP 均绑定 IPv4 回环。HTTP 验证精确 Host、存在时验证精确 Origin，并要求每次请求使用配对 Bearer。HTTP 使用无状态传输，无可重放的 MCP Session ID。
- stdio 配对由启动进程的环境提供，每次工具与资源查询重新检查有效期；连接定期发送心跳。Tunnel 的 Runtime Key 留在专用启动进程环境中，Bridge 入口删除其自身环境中的值。标准输出仅用于 MCP。调用方的操作系统账户需受信任，同用户进程内存和终端环境不属于 MCP 的隔离边界。
- 本机 Hub 连接使用显式直连 Agent。配对凭据进入本机授权 Header，离开 Bridge 前不执行外部 URL 请求。现有 Codex 子进程继承环境的 allowlist 不含 MCP 凭据或 Tunnel 密钥。
- 传输请求最大 16 KiB；Hub 响应最大 5 MiB；单个媒体文件最大 3 MiB。每个配对最多四个并行读取、每分钟 120 次授权检查；读取超时 8 秒。上游未结束的调用继续计入并发。
- 生产配置需将本机 Dashboard、Hub、Bridge 和 Tunnel 进程放在可信设备上，并保持 Tunnel 健康端点同样仅在回环监听。

## 数据边界

只从已登记的 Markdown 和已发布的 Unity 产物读取。文档按标识符读取，校验路径、文件类型、大小和秘密标记。Unity 截图和录屏读取校验所属项目、运行、产物、大小、文件签名和 SHA-256。文本输出有字段筛选、已知凭据格式脱敏和大小限制。这些规则无法识别所有任意形式的秘密，也无法识别截图或录屏画面中的敏感文字。配对前请确认该项目数据适合共享。

任务说明、Git Diff、评论、Unity 日志和项目文档是外部内容。MCP Instructions 和 Prompt Templates 要求将它们作为证据处理。服务端的类型校验和授权不接受这些内容中的指令。
